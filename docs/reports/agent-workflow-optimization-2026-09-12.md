# 工作库代理分工与使用体验优化验收

日期：2026-09-12。范围：工作库控制文件、角色、hooks 与手动生成器说明。
后续更正：用户明确主模型与推理强度由自己选择，已删除工作库对 Astra `ultra` 的固定覆盖。
下文的 Astra `ultra` 启动值及对照数据是更正前的验证记录，不是日常使用要求。
本次提交仅包含工作库控制文件及验收报告，不修改产品代码、线上系统、历史任务状态或重试计数。

## 交付结果

- 主模型与推理强度由用户选择，工作库不覆盖；定位与资料核对使用 Luna `medium`，小修复及执行验证保留 Luna `xhigh`，实现及常规独立审查使用 Sol `high`，困难问题可选 Astra `xhigh` 独立复核。
- 保留原六个角色，新增 `worker`、`independent_reviewer`。未指定角色的子代理默认为 Luna `medium`；没有必须出场的角色或固定代理链。
- `[agents]` 配置上限为六个子代理，主代理另计；实际平台容量更小时分批推进。取消旧的角色配额与“只能一个写入助手”，改为文件归属和接口依赖约束，主代理也遵守归属。仅主代理调度，不允许递归或额外进程绕过容量。
- 取消长任务目录、逐步记账、每回合 checkpoint 的自动要求。启动与提交提示不再读取活跃任务索引或注入任务列表。旧 CLI、历史记录、状态协议与 retry 限制保留，仅在明确选择旧工作流时适用。
- 项目路由、脏工作树保护、线上授权与主代理验收责任保持。短交接包含目标、证据、文件归属和验收条件。

### 全局配置的并行变化

实施前保存了全局文件哈希，没有备份或直接改写其中的凭据配置。验证期间观察到全局
默认模型变为 Spark `xhigh`，文件最后修改时间随后再次变化；本轮未发出写入该文件的
命令，实际写入来源未确定。
因此不能声称全局文件逐字未变。本轮保留该变化；曾在工作库单独固定 Astra `ultra`，
现已按用户澄清撤回，主模型和推理强度完全交还用户选择。
全局上下文 `1000000`、压缩 `900000` 未因本轮调整。

全局严格读取仍存在既有 `disable_response_storage` 未识别问题；不扩展本轮修改范围。
`--help` 成功不作为有效配置证明。现有 `codex_hooks` 别名有弃用警告，仍能启用 hooks；
本轮保留开关以避免额外扩大授权检查的变更面。

## 三类真实任务的新旧对照

两种方案每类各执行一次，使用相同主模型 Astra `ultra`、相同请求、相同初始源码，
独立临时 Git 仓库，不访问产品和线上系统。旧规则及角色使用修改前备份；两版旧/新
并发默认值按同一 `0.153.4` 支持的 `[agents]` 命名空间表达，避免比较配置解析失败。
自动 hooks 和自动 skills 在两组评估中均关闭；hooks 的实际函数行为另行隔离测试。
因此本实验比较局部任务执行，不能直接度量日常桌面使用的全部体验。

下表每格均为“旧 / 新”。耗时是 CLI 从启动至退出的墙钟秒数；token 为主代理累计
输入加输出，已含重复上下文和缓存输入，**不是整个代理树的费用**。

| 场景 | 秒数：旧 / 新 | 主代理总 token：旧 / 新 | 其中缓存输入：旧 / 新 | 正确性 |
| --- | --- | --- | --- | --- |
| 限定范围查找 | 79.8 / 77.1 | 129,202 / 147,428 | 116,736 / 125,440 | 两版通过 |
| 两个独立模块实现 | 143.3 / 134.6 | 214,664 / 165,138 | 187,776 / 137,472 | 两版通过 |
| 跨模块修复 | 200.6 / 184.4 | 352,263 / 291,783 | 302,336 / 258,432 | 两版通过 |

- 两版查找均返回正确归属与 `5397`，源码未改。两版实现和修复均通过外部复跑，原始测试文件哈希不变。
- 可见源码修改均一次完成，未观察到修改后测试失败导致的第二轮源码修正；子代理内部返工数据不可用。新修复增加了服务路径边界测试，最终七项测试通过。
- 除预期的修复前失败复现外，旧方案出现一次、新方案三次辅助命令失败，原因是不存在的可选路径或提前读取尚未生成的辅助测试；均自行恢复，无误授权停顿。
- 六次任务都使用一个辅助代理，没有自动建立运行目录。新方案允许零辅助，但这组样本没有测到零辅助选择；旧方案在这些短任务中同样没有触发运行目录，不能据此量化取消强制记账的收益。
- 独立模块实现采用主代理和一个助手并行、文件归属分离。跨模块修复由主代理统一修改共享 key/store 契约，助手补充验证，未观察到主代理与助手共享文件并发写入。
- 没有观察到主代理发起递归扩张；V2 未导出完整子代理内部事件，不能声称动态穷尽验证了递归限制或六子代理满负载。
- 三类新方案在这次抽样中都更快，但每类只有一个样本，缓存、服务延迟与任务拆分均影响结果，不能宣称稳定或统计意义上的提升。查找任务的新方案主代理 token 反而更高。

### 用量的可获得性

保存了每次主代理的输入、缓存输入、输出、推理输出、工具事件与累计 usage。
主会话 V2 协作返回的是任务名，没有可关联的子会话 ID；按本轮返回的主会话 ID 查询
`account/usage/read`，六次均未返回 threadUsage。子代理完整 token、计费 credits、美元
金额及子代理独立耗时均标为**不可用**，不以零代替。

新方案的这些小样本仍选用了 Luna 辅助（含默认模型），没有覆盖 Sol 的较大实现收益。
因此本轮不声称“总额度下降”或证明混合模型始终优于旧模型组合。新增角色诊断单独执行，
不混入三类任务的耗时比较。三类对照使用候选规则的冻结副本；测量完成后补充了
“无命名角色选择器时显式传入模型/强度”的兼容说明。六次原任务均未使用命名角色选择器，
没有为这项说明修订重复计费运行三类任务，因此它不是最终全部文字版本的完整重测。

## 新增角色启动诊断

首次诊断失败：本次 CLI V2 暴露的工具没有 `agent_type` 选择参数，调用同时漏掉必需的
`task_name`，两次请求均被解析器拒绝，没有启动助手。该失败保留在 `runtime-smoke`。

随后按实际接口补充兼容分派：主代理读取角色文件，传入必需的任务名、模型、强度及
短交接约束；支持命名角色选择器的客户端仍优先使用该选择器。`runtime-fallback` 实际
启动并收到了两个助手的最终回应，来源文件与 `5397` 的验收结果正确，源码哈希未变：

| 角色用途 | 实际请求参数 | 结果 |
| --- | --- | --- |
| worker | `gpt-5.6-sol` / `high` | 读取折扣归属并返回证据 |
| independent_reviewer | `gpt-6-astra` / `xhigh` | 独立读取 rounding 实现并返回证据 |

运行时声明四个总席位、最多三个助手，本次启动两个。没有将配置中的六当成实际六席位。
命名角色选择与角色 sandbox 参数在这个接口中不可选，故角色文件权限声明不是本次
诊断中已证实的技术隔离；只读约束被明确写入交接，实际源码未变。子代理内部模型/
推理遥测仍不可得，只能确认请求被接受且真实结果返回，不能独立证明后端模型身份。
这些限制已经写入 AGENTS.md 和 WORKER.md，避免后续将配置声明误报为运行事实。
